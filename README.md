# Soundtrap — The Game 🎹

A pixel point‑and‑click adventure: the origin story of Soundtrap. Chapter 1 — The Bank.
The game is **password‑protected**: it's shipped encrypted and only unlocks in the browser
when the correct password is entered.

![cover](cover.jpg)

---

## How the password gate works

`game.html` (the real game) is encrypted with **AES‑256‑GCM**, using a key stretched from your
password with **PBKDF2‑SHA256 (250 000 iterations)**. The result is baked into a self‑contained
`index.html` unlock page. What gets published is only the *ciphertext* — without the password there
is nothing to read. Decryption happens entirely in the visitor's browser; nothing is sent anywhere.

> `game.html` is the plaintext game and is listed in `.gitignore` — **never commit it.**
> Publish only `index.html` and `cover.jpg`.

---

## 1. Set the password / build

You need [Node.js](https://nodejs.org) installed (no packages required — it uses Node's built‑in crypto).

```bash
cd soundtrap-the-game
node build.js "your password here"
```

This writes `index.html` with the game encrypted inside. Re‑run any time to change the password.

> Pass the password **as an argument in quotes** (as above) — it's the reliable way, and it's required
> in editor/embedded terminals that don't support a hidden prompt. In a normal system terminal you can
> also just run `node build.js` and it will prompt for the password with hidden input.

**Pick a real passphrase** — a few words is far stronger than one short word, since anyone can try
to brute‑force a client‑side gate. Share the password with the birthday person separately (not in the repo).
(Passing it as an argument leaves it in your shell history; run `history -c` afterwards if you care, or
just pick a password you don't reuse anywhere.)

## 2. Test it locally

```bash
# from inside the folder:
python3 -m http.server 8000
# then open http://localhost:8000  and enter your password
```

(Opening `index.html` directly as a `file://` works too, but a local server matches how GitHub serves it.)

## 3. Put it on GitHub Pages

```bash
git init
git add index.html cover.jpg README.md .nojekyll .gitignore
git commit -m "Soundtrap — The Game (encrypted)"
git branch -M main
git remote add origin https://github.com/<your-username>/<repo-name>.git
git push -u origin main
```

Then on GitHub: **Settings → Pages → Build and deployment → Source: “Deploy from a branch”,
Branch: `main` / `/ (root)` → Save.** After a minute your game is live at:

```
https://<your-username>.github.io/<repo-name>/
```

Send that link **and** the password to the birthday person. 🎂

### Nice‑to‑haves
- **Social preview:** Settings → General → Social preview → upload `cover.jpg`, so the link shows the cover when shared.
- **Change the password later:** re‑run `node build.js`, then `git commit -am "rotate password"` and `git push`.

## Security note
This is a solid gate for a personal gift, not bank‑grade DRM. The whole encrypted game is delivered to
the browser, so anyone who has (or guesses) the password can play — and, with the password, could extract
the game. Use a strong passphrase and share it privately. That's plenty for keeping a birthday surprise
under wraps.
